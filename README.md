# Заявки на автоматизацию

Небольшой сервис, в котором сотрудник регистрируется, оставляет заявку на автоматизацию и позже меняет её статус. Данные лежат в Supabase. Каждый пользователь видит и меняет только свои заявки: это ограничивают политики Postgres, а не фильтр в интерфейсе.

## Локальный запуск

Нужны Node.js 22 и проект Supabase.

1. Создайте проект в [Supabase](https://supabase.com/dashboard).
2. Откройте SQL Editor и выполните [`supabase/schema.sql`](supabase/schema.sql) один раз. Скрипт создаёт таблицу `requests`, включает RLS и подтверждает почту при регистрации, чтобы после создания аккаунта сразу открывался список заявок.
3. Скопируйте `.env.example` в `.env.local`. В Dashboard → Project Settings → API возьмите Project URL и publishable key (`sb_publishable_...`):

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

4. Установите зависимости и запустите приложение:

```bash
npm install
npm run dev
```

Откройте http://127.0.0.1:3000. Ключ `service_role` приложению не нужен и в репозиторий не кладётся.

## Что умеет сервис

- Регистрация, вход и выход по почте и паролю.
- Заявка: название, описание и категория «Бот», «Интеграция», «Отчёт» или «Другое». Все поля обязательны. Новая заявка получает статус «Новая».
- Список показывает название, категорию, дату создания и статус.
- Свою заявку можно открыть и изменить, в том числе статус: «Новая», «В работе», «Завершена».
- Поиск по названию и фильтр по статусу сохраняются в адресе страницы.
- После сохранения видно сообщение об успехе. Если сохранить не удалось, на форме остаётся текст ошибки, а введённые поля не стираются.
- Пока сохранение идёт, кнопка недоступна. Повторная отправка в этот момент не создаёт вторую заявку.
- На узком экране список становится карточками, поля и кнопки растягиваются на ширину экрана.

## Доступ к данным

Политики RLS на `public.requests` разрешают роли `authenticated` только строки, где `user_id` совпадает с `auth.uid()`:

- читать и обновлять свои строки;
- создавать строку только со своим `user_id` и статусом `new`;
- удаление не разрешено.

Запрос с сессией другого пользователя не возвращает и не меняет чужую заявку. В интерфейсе такая ссылка выглядит как «Заявка не найдена».

## Публикация

Рабочий сайт: https://automation-requests.vercel.app

Репозиторий: https://github.com/askerrag/automation-requests

На Vercel заданы `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. GitHub к проекту Vercel не подключён, поэтому новый пуш сам сайт не обновляет: деплой делается отдельно.

После смены адреса в Supabase → Authentication → URL Configuration укажите `https://automation-requests.vercel.app` в Site URL. С текущей схемой регистрация не ждёт письмо, поэтому сайт открывается и без этого шага.

## Как помогали AI-инструменты

Приложение собрано в Cursor. Перед кодом сверился с актуальной документацией Supabase: сессия хранится в cookie через `@supabase/ssr`, проверка пользователя на сервере идёт через `getClaims()`, а обновление сессии — в `proxy.ts` (так устроен Next.js 16).

Сразу получилось создать проект Supabase, таблицу и политики RLS. Проверка двумя сессиями через API подтвердила, что чужая заявка не читается и не обновляется, а вставка со статусом не «Новая» или с чужим `user_id` отклоняется.

По пути всплыли такие проблемы:

- `npm install` несколько раз обрывался по таймауту сети. Повторная установка дошла до конца за счёт уже скачанного кэша.
- После ошибки валидации React сбрасывал форму и стирал категорию. Сброс формы отключён, поэтому текст ошибки остаётся рядом с введёнными полями.
- Повторный `requestSubmit` в одном такте всё равно доходил до сервера, пока блокировка стояла на всплытии события. Блокировка перенесена на фазу захвата: второй запрос на создание больше не уходит, в списке остаётся одна заявка.

Интерфейс проверен в Playwright: регистрация, вход с неверным паролем, создание, правка статуса, поиск, фильтр, обновление страницы, повторный вход, второй пользователь и узкий экран 390px.

## Известные недоработки

- Бесплатный проект Supabase может остановиться после долгого простоя. Его нужно включить в Dashboard, данные при этом сохраняются.
- Удаления заявок нет: в задании его не было.
- Если убрать триггер подтверждения почты и снова включить Confirm email, встроенная почта Supabase отправляет письма только участникам организации. В текущей схеме триггер подтверждает адрес при создании пользователя, и регистрация сразу открывает список.
- Поиск ищет подстроку в названии без учёта регистра. Описание в поиск не входит.
- В публичном репозитории нет `package-lock.json`. Зависимости ставятся по `package.json`.
